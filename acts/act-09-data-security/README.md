# act-09-data-security · 第九幕任务书（数据安全：一条红线）

## 一、任务书（对应剧本 M09 · 信任基石：数据安全的绝对红线）

- **本幕承担什么**：第八幕说要成为全行业认同的「尺子」；第九幕回答紧接着的问题——**企业接入以后，它的数据安不安全？**第七幕里工厂 Agent「读取 MES」，投资人一定会问：你们连进企业系统，会不会碰到机密？
- **核心命题**：**数据安全是项目发展的核心与必要性。**一家企业的资料被一条红线分开——哪些能用、哪些永不触碰、红线怎么守住。
- **整幕只讲数据安全**：不再单独演爬虫与封门潮（只在第 2 拍作为一份被挡回的「来源不明」资料出现，回扣第二幕），不单独演数据治理过程（红线三只出现在最后的铭牌上），不讲中立与评价体系（第八幕已覆盖）。
- **三条红线（计划书 4.4 原话）**：
  1. **明确开放**：只提供明确开放的数据，以及法律框架下允许的信息；
  2. **零触碰机密**：绝不涉及任何用户的商业机密与研发技术；
  3. **治理壁垒**：专注整理与管理难度极大的公开信息，以及需要专业挖掘的行业信息。
- **已定口径**：
  - 第 3 拍的事实陈述：**企业 Agent 部署在企业内部，在内部读取 ERP / MES；平台只经手答案，不存企业内部数据**（已与用户确认）；
  - 机密举例固定四项：**配方、研发工艺（研发技术）· 客户名单、成本底价（商业机密）**；
  - 不点名第二幕的封堵案例，不写任何未取得的合规认证名称；
  - 画面数字一律标「示例」（「2 万支，15 天」为示例需求）；不出现金额。
- **边界**：不重复第七幕的协商与确认单，只借用其中一个问题；不展开企业 AI 部署（最后一幕）。

## 三、演讲者备注（草稿）

1. **【M09-A · 一条红线】** 要让全行业放心接入，有一条底线必须从第一天就写死：数据安全，是这个项目发展的核心与必要性。一家企业有很多资料——产品规格、资质、检测报告，也有配方、工艺、客户名单和成本底价。我们用一条红线把它们分开：红线外的可以用，红线内的永不触碰。
2. **【M09-B · 红线外】** 红线外，我们只用明确开放、法律允许的信息：企业主动登记的、依据公开法规与标准的、公开的检测报告。每一份都有来源可查，才会变成标准数据卡。来源不明的、未经授权抓取的，一律不收——这正是第二幕那些平台关门要挡的东西，我们从一开始就不碰。
3. **【M09-C · 红线内】** 红线内，是企业的商业机密和研发技术：配方、工艺、客户名单、成本底价，我们绝不涉及。那第七幕里工厂 Agent 读取 MES 怎么办？企业的 Agent 部署在企业内部，在里面读自己的系统；越过红线的，只有一句答案——「可以，第 15 天交付」。数据留在企业里，平台只把答案带出来。
4. **【M09-D · 红线落定】** 每一家企业都守着自己的红线，同时接入同一个平台。三条红线从第一天写死：只用明确开放、法律允许的信息；绝不涉及商业机密与研发技术；我们的价值，来自把最难整理的公开信息整理好。边界清晰，全行业才敢放心接入。

## 四、视觉约定

- **视觉主风格**：延续第六至八幕「悬浮空间 + 实时景深」（零地面、暖白柔光穹顶、悬浮微尘）；2D 版面调色后叠加并随分辨率重绘，3D 标签写入深度参与景深。
- **配色语义**：红色只给红线本身与被挡回的资料；合法来源与企业 / 工厂用绿色；MCP 香槟金；客户问题蓝色；保险柜深钛色。
- **一幕一主角**：整幕主角是「一家企业的资料与那条红线」；每一拍只留这一拍的主角，其余元素退场或压暗。
