# 总装与维护（《AI 应用调香的发展路线与商业计划》路演）

> 本文说明 11 幕怎样组合成一整片、以后怎样改动，以及进度和决策记在哪里。
> 分幕内容与已定口径见 [分幕计划与决策](分幕计划与决策.md)，通用制作规范见 [制作与验收](制作与验收.md)。

## 一、组合方式

### 1. 三层结构

```
core/        共用引擎：渲染、节拍、转场、备注、总览、单幕运行器（全片共用一份）
acts/        11 幕，每幕一个目录，各自的模型、贴图、着色器、文案都在自己目录里
master/      总装：manifest.js 按播放顺序引用每幕选定的候选
```

- **各幕不合并成一个大文件**。每幕保留原始目录，可以单独打开、单独细调。
- **总装清单是唯一的跨幕连接点**。[master/manifest.js](../master/manifest.js) 里每幕一行 `import`，按顺序放进数组。换候选、调顺序都只改这一个文件。
- **单幕预览与整片使用同一套引擎**。单幕页面通过 `core/sandbox/act-runner.js` 运行，整片通过 `master/main.js` 运行，两者调用同一个 `createDeck`。单幕里看到的效果，就是整片里播出的效果。
- **共用文件按幕复制，不抽公共模块**。第六幕起的景深着色器、材质、道具、版面框架，每幕各有一份。这样改一幕不会牵动别的幕。代价是：修复一个共用问题时，要逐幕各改一次。

- **辅助**：A 自动播放（播到最后一拍自动停），N 演讲备注，P 备注副屏，O 缩略图总览，B 黑屏，F 全屏，M 静音，H 快捷键帮助。

## 二、保持各幕独立的规则

以下规则保证改一幕不会影响别的幕。前两条由 `npm run check` 自动检查，其余靠自觉，并由 `npm run verify` 兜底。

1. **不跨幕引用**。一幕只能引用自己目录里的文件和 `core/`、`three`。需要别幕的东西时复制一份过来，不要用 `import` 直接引用别幕的文件。
2. **场景 ID 全片唯一，确定后不要改**。ID 同时用作直达链接（`#场景ID-拍号`）和渲染缓冲的归属标识（`createCinematicDofPass(ctx, 场景ID)`）。改 ID 要同步改这两处。
3. **临时改动的渲染器全局状态必须还原**。例如叠 2D 版面时要关掉 `renderer.autoClear`，写法必须是先存 `prevAuto`、用完恢复。不要硬写 `true` 或 `false`。
   - 曾出过的问题：第五、六幕硬写 `autoClear = true`，单幕预览完全正常，但整片连播时第一至四幕的三维画面被清空，只剩文字。
   - 现在引擎每次渲染前会把 `autoClear` 和裁剪测试重置为默认值，作为第二道保险。
4. **2D 版面在调色之后叠加**。实现 `renderOverlay(gradedTarget)`；`render()` 里只在 `info.overlayAfterPost` 为假时叠版面（转场、快照时）。不这样做，文字会被色调映射压灰。可参照第七至十一幕的 `textures/editorial-overlay.js`。
5. **事件监听和媒体不要越出本幕**。全局监听要有本幕状态判断；视频、声音离开本幕要停。第二幕的视频用 350 毫秒看门狗，离开即暂停。

## 三、维护流程

### 1. 每次改动的固定步骤

1. **对齐**：先说清楚改什么、为什么改，与负责人对齐后再动手。
2. **建分支**：从 `main` 切分支，命名 `feat/act-XX-<主题>`；改引擎或总装用 `feat/<主题>`。
3. **在幕目录里改**：只动这一幕的文件，用单幕地址预览。
4. **自检**：依次运行
   ```sh
   npm run check            # 结构与跨幕引用检查
   npm run build            # 多入口站点
   npm run build:singlefile # 离线单文件
   npm run verify           # 整片验收
   ```
   `npm run verify` 依次检查：
   - 逐拍走完 11 幕；
   - 经真实转场跨过每一幕，画面平均亮度不得低于 12；
   - 从末幕后退回上一幕末拍；
   - 检视台、对比台和离线单文件都能打开；
   - 全程没有浏览器报错。

   截图存到 `outputs/master/verify-*/`。本机需要设置 `CHROME_PATH`（如 `C:/Program Files/Google/Chrome/Application/chrome.exe`）；软件渲染约需 2–3 分钟。
5. **记录**：更新该候选 `README.md` 的验证与优化记录；新的口径或取舍追加到 [分幕计划与决策](分幕计划与决策.md) 第三节。
6. **提交与合并**：负责人确认后，提交并以 `--no-ff` 合并回 `main`。推送也要等负责人确认。

### 2. 常见改动怎么做

| 想做的事 | 改哪里 | 注意 |
| :--- | :--- | :--- |
| 优化某一幕细节（文案、镜头、时长、配色） | 只改该幕目录 | 文案集中在 `models/actXX-data.js` 或版面文件；拍的时长在 `scene.js` 的 `beats` |
| 给某一幕做新候选 | `npm run new:candidate -- <幕目录> <候选名>`，或复制现有候选目录后改 `id` | 新候选的场景 ID 可与旧候选相同（同一时间只有一个进总装）；用 `core/sandbox/compare.html` 并排比较 |
| 换用另一个候选 | `master/manifest.js` 改该幕那一行 `import` | 同时更新幕 README 的「当前主选」和本文第一节的清单表 |
| 调整幕的顺序、增删一幕 | `master/manifest.js` 的 `import` 与数组顺序 | 各幕版面里写死了幕号（如「ACT 07」「07 / …」页脚），要到对应幕的版面文件里改；同步更新分幕计划第一节和本文清单表 |
| 修共用问题（景深、材质、版面框架） | 每个用到它的幕各改一次 | 先在一幕里改好验证，再逐幕同步；不要改成跨幕引用 |
| 改引擎（`core/`） | `core/` | 影响所有幕，必须跑完整 `npm run verify`，并抽查各幕单独预览 |

### 2. 分支与版本

- `main` 始终是可放映的整片：只合入通过了 `npm run verify` 的改动。
- 每幕或每个主题一个分支，合并后分支保留，便于追溯；确认不再需要时可以删除。
- 正式路演前建议给当次放映的版本打标签（例如 `git tag pitch-2026-12-xx`），并留存当次的 `dist-single/master/index.html`，以后可以随时找回当时放的版本。

### 3. 已知问题

- 跨幕转场约 0.85 秒内，第六至十一幕的 2D 版面会随画面一起过调色，短暂偏灰。影响小，暂不处理。
